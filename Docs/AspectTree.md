**0\. Цел на документа**

Този документ описва **аспектското дърво** - неговата архитектура, роли и поведение.

Фокусът е върху класа:

TVirtualStringTreeAspect = class(TVirtualStringTree)

Документът покрива:

- защо съществува аспектско дърво
- какво представляват възлите
- как се свързва с ADB / LNK / CMD
- как се използва за:
  - навигация
  - филтриране
  - търсене
  - визуализация на история
  - UI контекст
- разликата между:
  - ADB дърво
  - Филтърно дърво
  - CMD дърво

**🟦 1. Какво е аспектско дърво**

**Аспектското дърво не е просто UI компонент.**  
То е **визуална проекция на аспектската структура на данните**.

Основни характеристики:

✔ дървото **не държи данни**, а **връзки към данни**  
✔ всеки възел има **аспектски смисъл**  
✔ дървото е **детерминистично** - може да се възстанови изцяло от LNK + CMD  
✔ едно и също ADB може да има **няколко различни аспектски дървета**

**🟩 2. Основни роли на аспектското дърво**

Аспектското дърво изпълнява едновременно няколко роли:

**2.1. Навигация**

- показва логическата структура на обектите
- определя „контекста" за UI екрани
- избира _кой_ обект е активен

**2.2. Контекст за UI**

- кой екран да се покаже
- кои полета са релевантни
- кои колекции участват

**2.3. Филтриране**

- визуална дефиниция на условия
- групиране (AND / OR)
- избор на обектни клонове

**2.4. Search Engine вход**

- дървото дефинира _какво_ ще се търси
- SearchEngine работи **по дървото**, не по UI

**2.5. CMD визуализация**

- показва история на действията
- показва командите като логическо дърво

**🟧 3. TVirtualStringTreeAspect - специализация**

TVirtualStringTreeAspect е специализиран наследник на TVirtualStringTree, който:

- работи **директно върху memory-mapped данни**
- не алокира собствен NodeData динамично
- използва **PAspRec**, записан в LNK файла

**3.1. NodeData layout (PAspRec)**

PAspRec = ^TAspRec;

TAspRec = record

index: Integer; // индекс / допълнителен смисъл

vid: TVtrVid; // вид на възела (аспектски тип)

DataPos: Cardinal; // позиция в ADB (ако има)

end;

⚠️ **NodeData не е собственост на дървото**  
→ той е част от LNK файла

**🟥 4. Видове аспектски възли (TVtrVid)**

Всеки възел има **тип (vid)**, който определя поведението му.

Примери:

**4.1. Обектни възли**

- vvPatient
- vvPregled
- vvDiagnosis
- vvRecipe
- vvTherapy

➡ сочат към реални записи в ADB  
➡ имат DataPos

**4.2. Филтърни възли**

- vvFilterItem
- vvFieldFilter
- vvOperator
- vvObjectGroup
- vvRootFilter

➡ **нямат DataPos**  
➡ управляват логиката на търсене

**4.3. Командни възли**

- vvCmdInsert
- vvCmdUpdate
- vvCmdDelete
- vvCmdProp

➡ визуализират CMD файла  
➡ използват временен VTR (vtrTemp)

**🟩 5. ADB аспектско дърво**

**5.1. Източник**

- генерира се от **LNK файла**
- възлите са подредени според логическата структура

**5.2. Свойства**

- всички обектни възли имат DataPos
- дървото е „пълно" (всички записи)
- използва се за:
  - навигация
  - визуализация
  - търсене

**🟦 6. Филтърно аспектско дърво**

**6.1. Цел**

Филтърното дърво **не е копие на ADB дървото**.

То е:

- абстрактна структура
- дефиниция на _условия_
- вход за Search Engine

**6.2. Характеристики**

- възлите са **уникални по път**
- обектните възли са по един за тип
- няма DataPos
- държи само логика

**6.3. Magic Path Index**

За всеки възел се изчислява:

Sig := ComputeNodePathSig(Node);

Този подпис:

- е идентичен между ADB и Filter дървото
- позволява join между тях

**🟧 7. Join между ADB и Filter дърво**

Join логиката:

- ADB.PathIndex : Sig → List&lt;PVirtualNode&gt;
- Filter.PathIndex : Sig → FilterNode

Резултат:

TJoinBucket = record

Sig: UInt64;

AdbList: TList&lt;PVirtualNode&gt;;

FilterNode: PVirtualNode;

end;

➡ FilterNode „знае" кои ADB възли са му релевантни  
➡ index се записва в PAspRecFilter.index

**🟥 8. Аспектско дърво и Search Engine**

SearchEngine **не обхожда ADB директно**.

Процес:

- Потребителят променя Filter Tree
- Генерира се Magic Index
- За всеки FilterNode:
  - взима се AdbList
- Върху този списък се прилагат условията

Това позволява:

✔ бързо търсене  
✔ AND → подмножество  
✔ OR → обединение  
✔ incremental search

**🟩 9. Аспектско дърво и UI**

**9.1. Избор на възел**

Изборът на възел определя:

- коя колекция е активна
- кой Grid се показва
- кой FMX екран се зарежда

**9.2. Динамични екрани**

FMX екраните:

- не знаят за ADB
- не знаят за CMD
- получават **PAspRec + контекст**

Аспектското дърво е _мостът_ между:

ADB ↔ UI ↔ Search ↔ CMD

**🟦 10. CMD дърво (временен VTR)**

CMD визуализация използва:

- отделно TVirtualStringTreeAspect
- временни възли (vtrTemp)
- ReadCmd методи от генерираните класове

CMD дървото показва:

- Insert
- Update
- Delete
- Променени полета
- История на действията

**🟪 11. Защо аспектското дърво е ключово**

Без аспектско дърво:

❌ UI ще е твърдо вързан  
❌ Search ще е бавен  
❌ Няма контекст  
❌ Няма история  
❌ Няма логика за роли

С аспектско дърво:

✔ всичко е контекстно  
✔ всичко е динамично  
✔ UI е декларативен  
✔ Search е мащабируем  
✔ CMD е визуализируем

**🟩 12. Заключение**

TVirtualStringTreeAspect е:

**централният UI/логически гръбнак на Aspect Platform**

Той:

- не е просто дърво
- не е просто UI
- не е просто навигация

Той е:

**визуализация на аспектската философия**
